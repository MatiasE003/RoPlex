# AGENTS.md

## Repository State
- This repository contains a Manifest V3 Chrome extension for Roblox Home, user profile, inventory, and game pages on `https://www.roblox.com`.
- `manifest.json` injects only the minimal `content-activation.css` and classic `content.js` loader at `document_start` on Roblox pages. The loader activates Home replacement mode synchronously only on the recognized Home route, then imports the small isolated route controller under `content/`. The controller loads and caches one shared `content.css` link on first entry to Home or Profile plus one `profile.css` link on first entry to Profile, and waits for the required styles before mounting. It dynamically imports and caches the Home implementation graph on first entry to Home, or the Profile implementation graph plus its persisted mode controller on first entry to a profile; unrelated routes load neither presentation CSS nor renderer graph. Profile replacement mode is activated only after its persisted preference resolves, its styles load, and the extension root mounts. Those packaged modules and route styles are exposed only to `https://www.roblox.com/*` through `web_accessible_resources` because Chrome does not support module declarations for manifest content scripts. The route controller remains loaded on other Roblox routes so same-document navigation into Home or a profile can mount exactly one matching application root.
- The Home bootstrap reads the authenticated account from `users.roblox.com`, the user's Robux balance from `economy.roblox.com`, friends from `friends.roblox.com`, the authenticated user's custom names for those friends from `contacts.roblox.com`, presence from `presence.roblox.com`, circular headshots and game icons from `thumbnails.roblox.com`, and the authenticated Home discovery feed from `apis.roblox.com` through the background service worker.
- Game pages load `server-browser.css` and `server-browser.js`; `roblox-page-bridge.js` runs in the page's main world on Roblox pages so it can relay custom-element lifecycle and route changes, while game pages also use it for direct joins through Roblox's official `GameLauncher`.
- Game-page match patterns cover both `/games/*` and locale-prefixed paths such as `/es/games/*`; `https://www.roblox.com/*` is also a host permission because dynamic main-world injection uses `chrome.scripting`.
- `background.js` owns Roblox API orchestration, bounded cursor pagination, retry/backoff, and the expiring region/datacenter cache. Each Server Browser run is one operation-ID-scoped `chrome.runtime.Port` session with an `AbortController`: background overlaps pagination with a bounded analysis pool, batches region-cache access per page, and streams result chunks and progress. Region POSTs execute in the Roblox tab's main world so their origin/referrer match the website request; active MAIN-world requests are registered by operation so cancellation can abort them. `GameJoinRegion` is extracted from the JSON stored in `joinScript.SessionId` when Roblox does not return it as a direct property. The public IP from `joinScript.UdmuxEndpoints` is geolocated through `https://ipwho.is`, with request deduplication, rate-limit handling, and separate expiring IP and `DataCenterId` location caches.
- `network-rules.json` contains a single scoped MV3 `declarativeNetRequest` rule that sets Roblox's required `User-Agent` only for `join-game-instance` requests initiated by `www.roblox.com`.
- `inventory/badge-bulk-delete.js` and `inventory/badge-bulk-delete.css` run on standard and locale-prefixed user inventory pages. On the authenticated user's own `#!/badges` section, they add a top-right Bulk delete control, turn visible badge cards into a multi-page selection surface, show irreversible-action and progress states, and preserve failed selections when Roblox returns partial failures. The controls remain hidden when ownership cannot be verified and are removed when the user leaves the badges category.
- `background.js` validates badge inventory ownership against `users.roblox.com` before destructive requests and handles bounded sequential deletion through `DELETE badges.roblox.com/v1/user/badges/{badgeId}`. It obtains and reuses Roblox's `X-CSRF-TOKEN` from the initial `403`, retries transient failures with backoff, and reports per-badge success or failure to the inventory UI.
- The `content/` modules replace Roblox Home with the first production slice of the adaptable Home design. `main.js` owns eager route coordination and lazy renderer registration, `home-app.js` owns Home mounting and account bootstrap, `app-shell.js` owns the shared shell, `friends.js`, `game-feed.js`, and `home-search.js` own their UI domains, while `config.js`, `messaging.js`, and `ui.js` contain shared contracts and helpers. They request `GET_HOME_BOOTSTRAP`, `GET_HOME_FRIENDS`, `GET_HOME_CONTINUE`, `GET_HOME_FAVORITES`, and `GET_HOME_RECOMMENDED` from `background.js`, render the authenticated user's identity and avatar, update account-specific links, and expose independent loading, error, and retry states. Friends are sorted by presence and the first seven are shown. Hovering or focusing a friend lazily requests `GET_HOME_FRIEND_PREVIEW`, which renders social counts, join date, activity, profile navigation, and an official direct Join action when Roblox exposes a public game instance. The top-bar search debounces `SEARCH_HOME_USERS` requests as the user types, displays up to eight matching profiles with direct profile links, and offers searches for players, experiences, communities, or Roblox documentation. Continue renders up to 30 experiences in Roblox's feed order, Favorites renders up to 30 publicly accessible favorites in Roblox's favorite order, and Recommended renders up to 50 valid personalized results returned by Roblox as a four-column landscape grid. All game cards show a thumbnail, rating, live player count, and direct game navigation. Vertical mouse-wheel input over either horizontal carousel moves it sideways and remains contained at either edge instead of scrolling the page. Continue and Recommended share the same authenticated discovery response through a 30-second background cache.
- `content/routes.js` recognizes Home and user profile routes, `content/app-shell.js` owns the shared topbar/sidebar shell, and `content/profile-app.js` plus `content/profile-sections.js` replace profile pages with independent loading, error, and retry states. The profile bootstrap and Avatar start immediately, while one root-owned `IntersectionObserver` requests Creations, Favorites, Friends, Communities, and Badges shortly before they approach the viewport; profile anchors trigger their target immediately. The profile bootstrap resolves the target identity, authenticated viewer, viewer-specific custom nickname, social counts/status, and presence. Separate requests load every returned equipped avatar asset and emote with its public Robux price when available, up to 50 public creations, up to 50 favorites, all public friends, all communities, and the 16 most recent badges. Friends and communities append in bounded scheduled batches with lazy, asynchronous image decoding. Equipped avatar items render in a two-row horizontal carousel controlled by wheel, trackpad, or scrollbar. The page renders the remaining sections in one vertical flow without `See all` navigation; bounded results explicitly report truncation. Profile reads use bounded memory TTL caches, exact in-flight deduplication, shared full-avatar and per-universe game enrichment, and authenticated-viewer partitioning for viewer-specific results.
- `content/profile-mode.js` owns the persisted `chrome.storage.local` preference and the fixed profile-mode switch. The switch remains available in both modes: disabling it unmounts the extension profile and restores Roblox's original page, while enabling it remounts the redesign without a reload. Preference changes propagate to other open Roblox tabs through `chrome.storage.onChanged`.
- Profile headers use the authenticated viewer's custom nickname when one exists while retaining the canonical display name and username. Own profiles and signed-out views omit Add Friend, Message, and Follow. Other signed-in profiles use official friendship/follow-state checks, a real message link, and CSRF-protected friend/follow actions; existing friends do not receive an Add Friend control.
- `content-activation.css` owns the global Home/Profile activation and anti-flash selectors. Route-loaded `content.css` contains responsive shared-shell presentation scoped to the extension roots, while route-loaded `profile.css` contains Profile and profile-mode-switch styling scoped to their roots. Friend activity labels use blue for Online/Studio, green for a visible game name or privacy-limited Playing state, and muted gray for Offline.
- `server-browser.js` detects standard and locale-prefixed game PlaceIds, requires the user to choose whether Roblox should return fuller or emptier servers first, starts one background-owned analysis session, and supports explicit cancellation. It maintains keyed group/card nodes, appends or updates only changed live results, keeps Join state outside the DOM, and performs a final ordering pass at completion. Approximate locations come from the public UDMUX endpoint IP; compact labels prefer the administrative region over the city (for example, `São Paulo, Brasil`). Its global DOM observer exists only while locating Roblox's mount anchor, then a bounded lifecycle observer watches anchor replacement and disconnects outside the game-instances route.
- `server-browser.css` contains all Server Browser styling and follows Roblox's light/dark themes.
- There is no repo-local package manager, build system, linter, typechecker, CI config, or bundled entrypoint. Server Browser pipeline regression tests use Node's built-in test runner.

## Performance Optimization TODOs
- These TODOs record the August 2026 static performance audit. Future agents should validate the affected behavior and current code before editing, but should not need to repeat the repository-wide audit. Preserve independent loading/error states, route-aware same-document navigation, authenticated-account isolation, destructive-action safeguards, and the documented manual behavior while implementing them.

### P0 - Route Loading and Startup
- [x] **Lazy-load Home and Profile implementation modules by route.** `content/main.js` now statically imports only route/event contracts, caches independent dynamic import promises for the Home and Profile implementation graphs, and registers each renderer set only on first entry to its route. The Profile import also owns the deferred `profile-mode.js` preference watcher. Every async completion revalidates the current pathname before mounting, preserving direct and same-document navigation without stale or duplicate roots while unrelated routes evaluate neither renderer graph.
- [x] **Load route-specific CSS only when needed.** `manifest.json` now injects only `content-activation.css` at `document_start`. `content/main.js` starts and caches idempotent shared/Profile stylesheet requests by route, awaits the required links before mounting, retries failed links, and revalidates the route before activation. The global activation sheet prevents native Home flashes, while Profile remains native until its preference, renderer, and styles are ready. Shared presentation selectors are scoped to the extension roots, and unrelated direct routes load neither presentation stylesheet.
- [x] **Remove the Home startup dependency on the Profile preference.** `content/main.js::initializeRouteController()` currently waits for `getProfileRedesignEnabled()` before reconciling every route. Home does not need this preference. Reconcile and mount Home as soon as `document.body` exists; resolve the preference only for Profile. Do not hide a profile until the preference is known and an extension root can be mounted. Done when Home startup is not blocked by `chrome.storage.local`, a disabled Profile never briefly hides Roblox, and import/storage failures restore the native page.

### P0 - Profile Request and Rendering Cost
- [x] **Stage Profile section requests by viewport proximity.** Profile bootstrap and Avatar now start immediately, while one `IntersectionObserver` owned by `ProfileApp` requests the remaining sections within a bounded viewport margin. Per-generation section state deduplicates observer, anchor, and retry triggers; hash-only navigation and initial profile fragments trigger and scroll to their target without weakening stale-response guards.
- [x] **Render large Profile collections incrementally.** Friends and Communities now mount an empty resolved panel and append every returned record in batches of 24 using `DocumentFragment` plus idle/frame scheduling. Each batch checks the active profile generation, and below-fold friend/community images use lazy loading and asynchronous decoding while retaining image fallbacks.
- [x] **Deduplicate and briefly cache Profile reads by target user.** Safe Profile reads now use separate exact in-flight and bounded TTL/LRU maps. Viewer-specific Bootstrap/Friends results are keyed by authenticated viewer and target, revalidated against account changes, and invalidated after relationship mutations; public section results are target-scoped. Full-avatar thumbnails share one target-keyed request/cache across Bootstrap and Avatar, while overlapping Creations/Favorites share per-universe game, vote, and icon enrichment. Mutation results are never cached as reads.

### P0 - Server Browser Pipeline
- [x] **Replace one-message-per-server analysis with one background-owned operation.** Each run now uses one operation-ID-scoped `chrome.runtime.Port`. Background follows cursors until Roblox reports no next page while earlier pages enter a bounded worker pool, deduplicates `${placeId}:${jobId}`, batches region-cache reads and writes per page, and streams progress plus chunks of at most 24 results. The global region limiter and retry policy remain authoritative in background. The deterministic 5,000-server fixture verifies one session, all 50 page/cache batches, 5,000 streamed results, and first-page results before pagination completes.
- [x] **Add real cancellation for long server analyses.** Every operation owns an `AbortController` and is canceled on route exit, refresh/restart, the explicit Cancel action, or Port disconnect. Pagination, rate-limit waits, retries, geolocation, and cache writes check the signal. MAIN-world fetches register page-realm controllers by operation ID, allowing background cancellation to abort already injected requests. Canceled status is non-error UI state and operation IDs prevent stale chunks from entering a later run; the regression fixture verifies that cancellation aborts active MAIN-world work and starts no later region checks.
- [x] **Render live server results incrementally instead of rebuilding the tree.** Server and group state is keyed by JobId/location, live chunks append or update only affected cards, and Join clicks are delegated from the root. Join pending/error state lives in application maps and survives card updates. Filtering and the completion pass reorder existing keyed nodes, while `content-visibility: auto` limits below-fold rendering cost for large collections.
- [x] **Narrow Server Browser DOM observation.** A document-subtree observer runs only while locating `#rbx-public-running-games`; after mounting, a lifecycle observer watches the nearest stable boundary only for anchor/root replacement. Extension-owned mutations and unrelated mutations inside Roblox's server list are ignored, and both observers disconnect outside the game-instances route.

### P1 - Network, Retry, and Cache Infrastructure
- [ ] **Introduce a shared abortable HTTP layer with deadlines and per-origin budgets.** `background.js::fetchJsonWithRetry()` and several direct fetch paths have no request timeout, while independent callers can retry together. Add per-attempt timeouts, an overall operation deadline, full-jitter backoff, endpoint/method-specific retry policies, and bounded per-origin concurrency/cooldowns. Honor valid `Retry-After` values or fail fast instead of silently retrying earlier. Keep destructive badge/profile mutation policy separate from idempotent reads. Done when hung requests cannot keep UI operations pending indefinitely and retry storms are bounded.
- [ ] **Make caches optional and batch storage access.** Region/datacenter/geolocation cache read or cleanup failures currently can fail otherwise valid work, and cleanup scans `chrome.storage.local` broadly. Treat read failures as misses and remove/cleanup failures as non-fatal; never block public-server fetching on successful cleanup. Batch known-key reads/writes/removals. Prefer memory or `chrome.storage.session` for five-minute region entries and reserve persistent local storage for long-lived IP location data. Add an index/version strategy so expiry cleanup does not require `get(null)`. Done when storage failure degrades cache efficiency but not feature availability.
- [ ] **Scope all personalized caches and in-flight requests to the authenticated account.** `homeDiscoveryCache` and `homeDiscoveryRequest` are currently process globals even though the Omni Home response is personalized. Key them by authenticated user ID, invalidate them on account change, and prevent a new account from joining an old account's in-flight request. Apply the same rule to any viewer-specific Profile/contact data added to caches. Done when switching accounts cannot expose or reuse the previous account's Continue/Recommended data, even during an in-flight request.
- [ ] **Bound memory caches and separate stable from volatile data.** `homeFriendPreviewCache` is unbounded and combines stable profile/social data with short-lived activity/game data. Use size-bounded TTL/LRU caches, remove expired entries on access, deduplicate in-flight preview requests, and cache stable and activity portions with appropriate independent TTLs. Apply bounded deduplication to repeated search/thumbnail reads only after measuring benefit. Done when cache size is capped and repeated identical requests share work without extending stale presence excessively.
- [ ] **Persist only lifecycle-critical MV3 throttle state.** Service-worker suspension currently resets provider cooldowns and adaptive region rates. Persist `blockedUntil` and rate/cooldown state in `chrome.storage.session`, restoring it on worker wake, so a restart after `429` cannot immediately resume at the initial rate. Keep unresolved Promises, controllers, and ordinary short-lived response caches memory-only because they cannot be resumed safely. Done when worker restart preserves provider cooldown compliance without attempting to resurrect stale operations.

### P1 - Inventory and Shared DOM Work
- [ ] **Move bounded badge deletion into one background session.** Inventory currently sends one runtime message per badge and repeats authenticated-user lookup for every deletion. Accept a strictly bounded ID list in one request or Port session, validate sender/ownership once, process deletes sequentially in background, stream per-item progress, preserve failed IDs, and revalidate the account after meaningful delays/auth failures. Keep deletion concurrency at one unless Roblox documents a safe alternative. Done when deleting N badges no longer causes N extension RPC/auth-bootstrap cycles while preserving irreversible-action safeguards and partial-failure behavior.
- [ ] **Narrow Inventory observation and decoration.** `inventory/badge-bulk-delete.js` observes the entire document and rescans visible cards during selection. Observe the inventory route/container and `#assetsItems` only while the badge category is active; decorate only added/changed cards and disconnect elsewhere. Reconciliation itself must clear selection on every invalid route regardless of which navigation event fired. Done when unrelated page mutations do not trigger full card scans and category changes leave no stale selection state.
- [ ] **Reuse hot-path formatters and image primitives after larger work.** Hoist repeated `Intl.NumberFormat` instances in `content/ui.js`, `content/app-shell.js`, and `server-browser.js`. Consolidate a shared image helper that supports HTTPS validation, error fallback, eager/lazy policy, and async decoding. This is a low-impact cleanup and should not be prioritized over route loading, Profile staging, or Server Browser redesign. Done when render loops allocate no formatter per item and thumbnail failures retain the documented fallback UI.

### P2 - Architecture Required to Sustain the Optimizations
- [ ] **Convert and split the service worker into ES modules by domain.** `background.js` currently combines RPC dispatch, Home/Profile orchestration, CSRF mutations, pagination, server-region analysis, geolocation, rate limiting, and cache storage in one file. Change the manifest background entry to `{ "service_worker": "background/main.js", "type": "module" }` and extract modules around existing behavior: `rpc/router`, `rpc/contracts`, `http/roblox-client`, `http/retry-policy`, `home/service`, `profile/service`, `inventory/badge-service`, `servers/public-servers`, `servers/region-analyzer`, `servers/geolocation`, and `servers/cache`. Make the smallest behavior-preserving moves first; do not combine this structural change with altered API semantics without tests. Done when background domains can be syntax/unit tested independently and the listener entrypoint only dispatches validated messages.
- [ ] **Centralize message and operation contracts.** Message strings, error-envelope decoding, event names, page limits, and retry settings are duplicated across `content/config.js`, `content/messaging.js`, `server-browser.js`, inventory, the bridge, and background. Create a shared/versioned contract source usable by extension-world modules and validate request/response payloads at boundaries. Keep the service worker authoritative for effective limits and return those limits in responses for UI text. Done when callers do not duplicate effective backend limits and unknown message types are rejected before unrelated field parsing.
- [ ] **Add measurement and regression tooling before claiming completion.** Establish a minimal repository-local test setup and CI when implementation begins. Cover route parsing, account-keyed cache isolation, geolocation cache round trips, retry/cancellation, Profile staged loading, and a deterministic 2,000-server fixture. Record request counts, cache hits/misses, canceled operations, DOM node counts, long tasks, and time to first server result. Update the Verification section and this file with exact commands after adding tooling. A performance TODO is complete only when behavior checks pass and measurements show the intended request/DOM reduction rather than only a file-structure change.

### Performance Guardrails
- Do not remove Roblox's hidden native application or suspend its runtime without profiling first; it may own routing, chat, account switching, or launcher behavior. Measure hidden-root mutations, network activity, CPU, and heap growth before attempting an invasive change.
- Do not increase badge deletion concurrency or Roblox join-region request rates as a performance shortcut. Preserve sequential destructive operations and the configured global provider limits.
- Do not introduce a bundler solely for code splitting; native extension ES modules and dynamic imports are sufficient unless a separate measured need appears.
- Prefer the smallest independently verifiable optimization. Preserve stale-response guards until real cancellation is proven end to end.
